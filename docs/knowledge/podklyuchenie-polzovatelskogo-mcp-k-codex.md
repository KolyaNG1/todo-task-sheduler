# Подключение пользовательского MCP-сервера к Codex

[← К глобальным знаниям](index.md)

## Кратко

MCP (Model Context Protocol — протокол подключения внешних инструментов) даёт
Codex доступ к функциям внешнего сервера. API не нужно «встраивать в память»
модели: его регистрируют в клиенте Codex и отдельно настраивают авторизацию.

## Подтверждённые сведения

- **Подтверждено:** для удалённого сервера нужен адрес, поддерживаемый транспорт и схема авторизации.
- **Подтверждено:** для локального сервера нужна команда запуска и необходимые переменные окружения.
- **Подтверждено:** пользовательские MCP-приложения должны иметь явно описанные сервер, авторизацию и набор опубликованных инструментов.
- **Подтверждено:** токены и ключи не передаются в чат; их задают в защищённой конфигурации клиента или окружении.
- **Подтверждено:** после изменения локальной конфигурации может потребоваться перезапуск Codex; это не меняет набор инструментов уже запущенной hosted-сессии автоматически.
- **Подтверждено для TASK_004:** сервер Stitch использует адрес `https://stitch.googleapis.com/mcp` и заголовок `X-Goog-Api-Key` по данным пользователя.
- **Решение:** Stitch MCP и Codex будут использоваться вместе для создания фронтенда сервиса: Stitch подготавливает экраны, варианты и дизайн-систему, Codex реализует их в коде проекта.

## Практический шаблон запроса на настройку

Пользователь может прислать:

1. название сервиса и что именно нужно делать;
2. URL MCP-сервера **без секретных параметров** или команду запуска;
3. транспорт: потоковый HTTP, SSE (поток событий от сервера) или стандартный ввод-вывод;
4. вид авторизации: OAuth, заголовок, переменная окружения или другое;
5. список нужных инструментов.

Секрет нужно обозначить как `<SECRET>` и не присылать настоящее значение.

Безопасный фрагмент для этого сервера:

```toml
[mcp_servers.stitch]
url = "https://stitch.googleapis.com/mcp"

[mcp_servers.stitch.http_headers]
"X-Goog-Api-Key" = "<SECRET>"
```

В исходном сообщении Markdown-разметка ссылки и запись заголовка были объединены
в одну строку, поэтому такой фрагмент нельзя вставлять в TOML без исправления.

## Рабочий процесс разработки фронтенда

1. В Stitch создаются экраны, варианты интерфейса и дизайн-система.
2. Codex получает эти материалы через MCP (протокол внешних инструментов).
3. Codex пишет и изменяет фронтенд-код в репозитории: компоненты, стили, маршруты и интеграцию с сервером.
4. Stitch используется для дальнейших изменений визуальной части, а Codex переносит их в код.

Stitch MCP не заменяет репозиторий, сборщик и проверку приложения: он является
источником визуальных материалов и операций над интерфейсом.

## Гипотезы и непроверенные места

- «Google Switch» может быть внутренним названием сервиса; его точный продукт и поддерживаемый транспорт ещё не определены.
- Возможность подключить сервер именно к текущей сессии зависит от клиента Codex, рабочего пространства и его разрешений.

# Синхронизация планировщика с Google Календарём

[← К глобальным знаниям](index.md)

## Кратко

**Подтверждено:** будущая интеграция осуществима. Прикладной слой планировщика
уже отделён от HTTP и SQLite, поэтому внешний адаптер не должен менять правила
автоплана. Начинать следует с импорта событий Google как занятого времени только
для чтения, затем при необходимости экспортировать блоки планировщика в
отдельный календарь.

## Рекомендуемый порядок

1. Пользователь в интерфейсе даёт разрешение Google через OAuth 2.0 — протокол,
   в котором он сам подтверждает приложению ограниченный доступ к календарю.
2. Сервер читает выбранный календарь и показывает его события как внешнюю
   занятость. Автоплан не размещает задачи поверх этих интервалов.
3. По явному выбору пользователя сервер создаёт и обновляет блоки планировщика
   в отдельном календаре «Планировщик», не изменяя личные события.
4. Только после отдельного проектирования конфликтов добавить двусторонний
   обмен одного выбранного календаря.

## Данные и границы адаптера

- Нужны отдельные таблицы для подключённой учётной записи, выбранного календаря,
  сопоставления локального и внешнего события, последнего маркера синхронизации,
  версии внешнего события и канала уведомлений.
- Обновляемые ключи доступа хранятся вне `artifacts/`; в базе достаточно
  безопасной ссылки на хранилище секретов и служебных метаданных.
- Внешние события не следует принудительно превращать в `FixedEventRule`:
  у них есть собственные повторения, отмены, участники и версия. Адаптер отдаёт
  в планировщик лишь нормализованные занятые интервалы.
- Для исходящих изменений использовать существующую таблицу исходящих событий,
  чтобы повторная попытка не создавала дубликаты.

## Согласование изменений

**Предложение:** первыми правилами сделать: внешние события только занимают
время, экспортируемыми управляет планировщик, а конфликт одного и того же
события останавливает автоматическое обновление и просит пользователя выбрать
версию. Для каждого сопоставления хранить внешний идентификатор, версию,
контрольную копию последней синхронизации и отметку удаления.

Google поддерживает полную первичную выгрузку и последующие изменения по
маркеру синхронизации. При недействительном маркере нужно повторить полную
синхронизацию. Уведомления Google сообщают только о том, что данные изменились:
после них всё равно выполняется добавочная синхронизация.

## Ограничения локального запуска

**Подтверждено:** для уведомлений Google нужен публичный HTTPS-адрес, поэтому
в текущем локальном запуске они не подходят. Достаточны кнопка «Синхронизировать»
и синхронизация при открытии приложения. Фоновый обмен после закрытия приложения
потребует постоянного серверного процесса и безопасного хранилища секретов.

# Выводы TASK_004 — Подключить пользовательский MCP API Google к Codex

[← К описанию](./004_descr.md) · [Журнал](./004_logs.md)

## Краткий итог

Подключение пользовательского Google MCP-сервера к Codex требует настройки клиента,
а не дообучения модели. Адрес и имя заголовка получены; для проверки соединения
нужны локальная подстановка ключа и перезапуск клиента.

## Подтверждённые результаты и доказательства

- **Подтверждено:** MCP (Model Context Protocol — протокол подключения внешних инструментов) передаёт Codex доступ к опубликованным инструментам сервера; модель не «запоминает» API через сообщение в чате.
- **Подтверждено:** для настройки нужны безопасные метаданные: URL удалённого сервера или команда локального запуска, транспорт (например, потоковый HTTP или запуск через стандартный ввод-вывод), схема авторизации и список нужных действий.
- **Подтверждено:** секреты не следует отправлять в чат. Их задают в менеджере секретов, переменных окружения или настройках клиента.
- **Подтверждено:** после изменения локальной конфигурации может понадобиться перезапуск локального клиента; это не гарантирует появление MCP-инструмента в уже работающей hosted-сессии.
- **Подтверждено:** пользователь указал удалённый сервер `https://stitch.googleapis.com/mcp` и заголовок `X-Goog-Api-Key`; секретное значение не раскрыто.
- **Подтверждено:** текущий `%USERPROFILE%\\.codex\\config.toml` содержит другие настройки, но блока `[mcp_servers.stitch]` в нём нет.
- **Подтверждено:** блок Stitch добавлен в `%USERPROFILE%\\.codex\\config.toml` на строках 136–140 с безопасной меткой вместо ключа.
- **Подтверждено:** файл на диске не пустой: размер 4355 байт; проблема относится к способу открытия ссылки в VS Code, а не к содержимому конфига.
- **Подтверждено:** Stitch зарегистрирован через `codex mcp add`, виден в `codex mcp list` как включённый сервер.
- **Подтверждено:** удалённый MCP-запрос `initialize` вернул HTTP 200 и не сообщил об ошибке ключа.
- **Подтверждено:** MCP-запрос `tools/list` вернул HTTP 200 и 15 инструментов Stitch: проекты, экраны, дизайн-системы и связанные операции.
- **Решение:** фронтенд сервиса будем создавать совместно через Stitch MCP и Codex: Stitch отвечает за экраны, варианты и дизайн-систему, Codex — за реализацию интерфейса в коде проекта.
- **Подтверждено:** подключённый набор Stitch достаточен для подготовки визуальной основы фронтенда; запись готового приложения в репозиторий остаётся задачей Codex.
- **Исправление синтаксиса:** URL должен быть обычной строкой, а заголовок — отдельной таблицей TOML:
  ```toml
  [mcp_servers.stitch]
  url = "https://stitch.googleapis.com/mcp"

  [mcp_servers.stitch.http_headers]
  "X-Goog-Api-Key" = "<СЕКРЕТ>"
  ```

## Полезные наблюдения

- Название «Google Switch» остаётся неоднозначным, но адрес Stitch уже известен.
- Текущая сессия имеет собственный набор доступных инструментов; присланный URL сам по себе не добавит новый инструмент в этот набор.

## Проблемы и преграды

- В текущем уже открытом чате инструменты могут ещё не отображаться до нового сеанса Codex.

## Как решались проблемы

- Пользователю нужно сообщить только конфигурационные метаданные, без токенов и ключей.

## Открытые вопросы

- Нужно открыть новый сеанс Codex и проверить, что в нём доступны инструменты Stitch.
- При реализации фронтенда нужно связать результаты Stitch с конкретным проектом и его технологическим стеком.

# Выводы TASK_025 — Переработать планировщик и закрыть аудит

[← К описанию](./025_descr.md) · [Журнал](./025_logs.md)

## Краткий итог

Переработка начата с сохранности данных и календарного ядра. Созданы
проверяемые резервные копии, исправлена цепочка миграций, добавлено UTC-хранение
для старых данных, а также внедрены цели и самостоятельное завершение блоков.

## Подтверждённые результаты и доказательства

- **Подтверждено:** штатный запуск на существующей базе завершился HTTP 200,
  создал схему 0004 и записал маркер одноразовой нормализации UTC.
- **Подтверждено:** чистая временная база проходит `alembic upgrade head` и
  содержит `goals` и `tasks.goal_id`.
- **Подтверждено:** 14 автоматических тестов проходят, включая сценарии точной
  длительности автоматического плана, восстановления удалённой задачи и
  наследования параметров направления.
- **Подтверждено:** фронтенд синтаксически проверен после введения отмены
  устаревших загрузок и строгой сверки оптимистичного блока.
- **Подтверждено:** добавлены цели с привязкой задач, завершение отдельного
  блока, недельная сводка, состояния уведомлений и регрессионные проверки
  повторного размещения/конфликтов.
- **Подтверждено:** быстрая навигация по календарю отменяет устаревший запрос,
  а фоновая синхронизация использует одну сводку сервера вместо двух
  расходящихся ответов. Внешние шрифты исключены из стартовой страницы.
- **Подтверждено:** выполненный блок можно убрать крестиком из плана; он
  переводится в отменённое состояние без физического удаления из базы.
- **Подтверждено на существующих данных:** повторное удаление блока безопасно
  и возвращает 204. Это исключает ошибку при клике по устаревшей карточке,
  которая уже была убрана предыдущим запросом.
- **Подтверждено:** оценка задачи и настройка направления принимают любую
  положительную целую длительность, включая 15 и 20 минут; календарная сетка
  по-прежнему ограничивает только время начала блока.
- **Подтверждено:** в банке задач доступны сортировки по сроку и по убыванию
  важности; навигация и банк задач сворачиваются независимо без потери
  возможности их вернуть.
- **Подтверждено:** цель содержит упорядоченную последовательность задач и
  процент достижения, взвешенный по оценке задач. Её параметры и порядок
  редактируются отдельной формой страницы, а не модальным окном.
- **Подтверждено:** задача, созданная по общему API с `goal_id`, сразу читается
  в составе цели; интерфейс после таких действий перезагружает и общий список,
  и открытый экран цели.

## Полезные наблюдения

- В SQLite значение `DateTime(timezone=True)` всё равно читается без пояса;
  надёжность обеспечивается только правилом записи UTC и одноразовой миграцией
  старых наивных локальных значений.
- Для завершения из расписания состояние должно жить у `ScheduleBlock`, а не
  выводиться из общего статуса `Task`; это позволяет сохранять блок в истории.

## Проблемы и преграды

- Полная модель экземпляров повторяющихся задач, расширенные отчёты и
  окончательное деление фронтенда на файлы ещё находятся в работе текущей
  задачи. Корзина доступна через HTTP и настройки, но не имеет срока
  автоматической очистки.

## Как решались проблемы

- Перед схемой 0004 вручную создана копия
  `artifacts/backups/planner-pre-refactor-20260910-160953.sqlite3`; запуск
  дополнительно создал автоматические копии перед схемой и UTC-преобразованием.
- Исторические строки дат преобразуются ровно один раз; время преобразования
  хранится в `artifacts/manifest.json`.

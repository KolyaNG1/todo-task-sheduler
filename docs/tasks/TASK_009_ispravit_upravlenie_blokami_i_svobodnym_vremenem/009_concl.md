# Выводы TASK_009 — Исправить управление блоками и свободным временем

[← К описанию](./009_descr.md) · [Журнал](./009_logs.md)

## Краткий итог

Недельная сетка получила явное удаление свободного времени и три действия
планового блока. Перенос блока теперь использует один сохранённый источник и
не может случайно обработать другую карточку или блок.

## Подтверждённые результаты и доказательства

- **Подтверждено:** у каждого видимого свободного интервала есть крестик. Он
  сохраняет оставшиеся интервалы выбранной даты, поэтому отменяет только
  выбранное свободное время.
- **Подтверждено:** у блока плана есть запуск таймера, изменение времени в
  окне с дискретностью 15 минут и снятие с плана. Последнее отменяет блок, но
  оставляет саму задачу активной.
- **Подтверждено:** перенос опирается на один объект `dragSource`, а не на
  данные нескольких целей браузерного события; длительность берётся разницей
  точных временных меток блока.
- **Проверка:** `node --check frontend/app.js`, `pytest backend/tests -q`
  (6 успешно) и запросы к API и интерфейсу вернули `200`.

## Полезные наблюдения

- Кнопки внутри перетаскиваемого блока должны быть исключены из начала
  перетаскивания, иначе нажатие на действие может интерпретироваться браузером
  как перенос.

## Проблемы и преграды

- Пользовательский браузер не показывает скрытые до наведения действия в
  дереве доступности, поэтому наличие кнопок проверялось по актуальной разметке
  и загрузке страницы; удаление пользовательских данных в проверке не
  выполнялось.

## Как решались проблемы

- Для удаления интервала применяется существующее сохранение набора интервалов
  даты: клиент исключает нужный интервал и отправляет оставшиеся значения.
- Для снятия с плана применяется существующий API отмены блока, который не
  удаляет задачу.

# TASK_027 — Расширить задачи и историю работы планировщика

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./027_logs.md)
- [Выводы](./027_concl.md)

## Цель

Расширить планировщик так, чтобы работа по задаче имела прозрачную историю
сессий, а крупные задачи можно было разложить на произвольное дерево
чекпоинтов. Одновременно устранить два локальных дефекта интерфейса и запуска.

## Границы

### Входит

- Отображение и удаление короткого (15-минутного) промежутка рабочего времени.
- Исправление кодировки заголовков двух окон, создаваемых запускатором Windows.
- Серверное и пользовательское представление истории сессий: обычная
  хронология остаётся, альтернативный вид группирует интервалы внутри задачи.
- Дерево задач произвольной глубины внутри цели: родительские пункты,
  чекпоинты, порядок, вычисляемый прогресс и запрет планирования не-конечных
  пунктов.
- Компактные карточки активных целей с процентом прогресса на главном экране.

### Не входит

- Внешние исследования интерфейсов других сервисов и синхронизация с ними.
- Изменение существующей модели направлений и тегов.

## Требования пользователя

- 2026-09-11 — исходный запрос: Расширить задачи и историю работы планировщика.
- 2026-09-11 — у рабочего промежутка длительностью 15 минут крестик удаления
  обязан помещаться и оставаться доступным.
- 2026-09-11 — сессии, начатые у задачи, должны открываться как список
  временных отрезков внутри этой задачи; прежний хронологический вид сохраняется
  и переключается кнопкой.
- 2026-09-11 — крупные задачи должны поддерживать чекпоинты и произвольную
  иерархию внутри цели; в календарь попадают только конечные пункты.
- 2026-09-11 — прогресс активных целей должен быть виден маленькими карточками
  на главном экране.
- 2026-09-11 — названия окон, создаваемых `Запустить планировщик.bat`, не
  должны отображаться иероглифами.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] Короткий промежуток рабочего времени имеет доступную кнопку удаления.
- [x] История имеет переключаемые хронологический и групповой режимы;
  раскрытие задачи показывает интервалы её сессий.
- [x] Вложенная задача получает родительскую задачу, наследует цель и не может
  быть размещена, пока у неё есть дочерние пункты.
- [x] Прогресс задач и целей считается только по конечным пунктам дерева.
- [x] На главном экране отображаются карточки активных целей.
- [x] Запускатор задаёт кодировку UTF-8 и заголовки окон читаются.
- [x] Проверки кода, автоматические тесты и `python scripts/docs_ctl.py check`
  завершились успешно.

## План

1. Зафиксировать модель дерева задач и совместимое расширение SQLite.
2. Добавить серверные сценарии дерева и выдачи истории работы по задачам.
3. Добавить интерфейс дерева, истории и карточек целей.
4. Исправить короткий слот и запускатор.
5. Проверить сценарии через API, браузер и автоматические тесты.

## Допущения и ограничения

- Цель остаётся корнем верхнего уровня; узлы дерева — обычные задачи.
- Оценка и прогресс родительской задачи являются производными от её конечных
  потомков, чтобы их нельзя было случайно посчитать дважды.
- Существующие плоские задачи остаются конечными и продолжают работать без
  переноса данных.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- **Решение:** использовать самоссылочную связь `Task.parent_task_id`, а не
  копировать таблицу целей. Так один и тот же сценарий работает для проекта,
  спринта и чекпоинта любой глубины, не создавая второй источник истины.
- **Решение:** считать планируемыми только листья дерева. Это не позволяет
  одновременно разместить крупную задачу и её детали.
- **Решение:** хранить отрезки в уже существующих `WorkSessionSegment` и
  добавить представление, а не дублировать фактическое время в задаче.

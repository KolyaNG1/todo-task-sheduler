# TASK_049 — Преобразовать направления в проекты

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./049_logs.md)
- [Выводы](./049_concl.md)

## Цель

Преобразовать пользовательскую сущность «Направление» в полноценный «Проект»:
сохранить существующие данные и связи задач, добавить проектам собственную
страницу, дерево задач, прогресс и ближайший срок, а создание задач связать с
проектными настройками по умолчанию.

## Границы

### Входит

- Переименование сущности во всём пользовательском интерфейсе.
- Совместимый программный интерфейс проектов без разрушения старых адресов.
- Панель проектов с прогрессом, количеством задач и ближайшим активным сроком.
- Страница проекта с произвольным деревом групп и конечных задач.
- Создание корневых и дочерних задач из проекта с наследованием проекта.
- Наследование проектных настроек задачами, создаваемыми на главной странице.
- Автоматическое сохранение текущих направлений и всех привязанных к ним задач
  как проектов с теми же именами.
- Проверка серверных тестов и основных пользовательских сценариев в браузере.

### Не входит

- Отдельное копирование строк направлений в новую таблицу: оно создало бы риск
  потерять или раздвоить существующие связи.
- Новый календарь, журнал заметок проекта и отдельная система участников:
  запрос покрывается текущими задачами, сроками и учётом работы.

## Требования пользователя

- 2026-09-21 — переименовать «Направления» в «Проекты».
- 2026-09-21 — проекты должны быть похожи на цели и содержать иерархические
  задачи.
- 2026-09-21 — на карточке проекта нужен ближайший срок.
- 2026-09-21 — существующие направления и привязанные задачи должны без потерь
  стать проектами с прежними именами.
- 2026-09-21 — проект должен задавать наследуемый контекст при создании задачи с
  главной страницы.
- 2026-09-21 — каждый проект должен открываться на отдельной странице, а его
  параметры должны редактироваться только внутри этой страницы.
- 2026-09-21 — карточка проекта должна выделяться оранжевым, если до ближайшего
  активного срока осталось менее 24 часов, и красным, если срок уже прошёл.
- 2026-09-21 — список и дерево задач в целях и проектах должны использовать
  единый карточный стиль основного списка задач, не теряя глубину дерева,
  сворачивание веток и управляющие действия.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] В интерфейсе больше нет пользовательского раздела «Направления».
- [x] Все прежние направления видны как проекты с прежними задачами.
- [x] На панели проекта корректно показаны прогресс и ближайший незавершённый
  срок.
- [x] Срочный проект выделяется оранжевым, просроченный — красным, причём
  просрочка имеет приоритет над срочностью.
- [x] В проекте можно создавать и просматривать произвольную иерархию задач.
- [x] Деревья целей и проектов состоят из единообразных карточек задач;
  вложенность читается по отступам и соединительным линиям, ветки сворачиваются.
- [x] Новая задача наследует выбранный проект и его настройки; дочерняя задача
  остаётся в проекте родителя.
- [x] Старые адреса программного интерфейса направлений продолжают работать.
- [x] Автоматические тесты и ручная проверка основных сценариев пройдены.
- [x] Результат задачи получен и проверен.
- [x] Выводы и проблемы описаны.
- [x] Глобальные знания и решения обновлены.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Зафиксировать модель проекта и безопасный путь преобразования данных.
2. Расширить хранение и программный интерфейс проектов, оставив совместимость.
3. Переделать раздел в панель и подробную страницу проекта с деревом задач.
4. Обновить формы задач и целей, а также архив.
5. Проверить автоматическими тестами и в запущенном приложении.
6. Обновить знания, решение и состояние документации.

## Допущения и ограничения

- Внутреннее имя таблицы `directions` и поле `direction_id` временно остаются
  неизменными как слой совместимости. Пользователь и новый программный интерфейс
  работают с термином «проект».
- Ближайшим считается минимальный срок незавершённой и неархивной задачи проекта;
  если у задач сроков нет, используется общий срок проекта.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- **Выбрано:** развить существующую запись направления до проекта на месте.
  Стабильные идентификаторы сохраняют все привязки задач и меток без массовой
  миграции данных.
- **Отклонено:** новая таблица проектов и копирование направлений. Такой вариант
  требует массово переписать внешние ключи, усложняет откат и создаёт риск
  дубликатов.
- Дерево проекта использует уже существующие `parent_task_id` и
  `is_checkpoint`: группа может быть неисполняемой либо одновременно считаться
  задачей, а листья остаются обычными задачами расписания.

# TASK_006 — Реализовать фронтенд и выполнить первый запуск

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./006_logs.md)
- [Выводы](./006_concl.md)

## Цель

Создать самостоятельный первый срез браузерного интерфейса: недельную сетку с
панелью задач и действиями главного сценария. Интерфейс должен обращаться только
к HTTP API сервера, чтобы впоследствии его можно было заменить без изменения
предметной логики, и должен быть проверен локальным первым запуском.

## Границы

### Входит

- Использование макета и визуальной системы проекта Stitch как источника для
  первого экрана.
- Статический клиент в каталоге `frontend/`, отделённый от `backend/`.
- Чтение стартовых данных, недели и списка задач через API.
- Добавление задачи, рабочего времени и неподвижного события через модальные
  окна; выбор задач, предварительное планирование и применение безопасных
  предложений.
- Управление текущей рабочей сессией и локальный первый запуск на портах 5173
  и 8000.

### Не входит

- Полная реализация отдельных разделов «Задачи», «Направления», «Итоги» и
  «Настройки» — они пока обозначены в навигации.
- Перетаскивание блоков, редактирование нескольких интервалов на одну дату,
  цели, Telegram и программный агент.
- Публикация приложения в интернет.

## Требования пользователя

- 2026-09-09 — исходный запрос: Реализовать фронтенд и выполнить первый запуск.
- 2026-09-09 — фронтенд должен быть сделан через MCP и учитывать внешний вид
  из Google Stitch; пользователь просит выполнить первый запуск.

## Критерии завершения

- [x] Главная недельная страница, панель задач и модальные окна реализованы.
- [x] Клиент читает и изменяет данные только через API.
- [x] Первый локальный запуск и доступность API подтверждены.
- [x] Выводы и глобальные знания обновлены.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Сопоставить `DESIGN.md`, макет Stitch и доступные ручки API.
2. Создать независимый статический клиент первой версии.
3. Проверить синтаксис, HTTP-доступность и основные окна в браузере.
4. Зафиксировать запуск и продолжить следующими разделами интерфейса.

## Допущения и ограничения

- В проекте не удалось автоматически создать шаблон из пакета `@openai/sites`:
  его пакет не доступен в настроенном реестре зависимостей. Поэтому первый
  срез реализован как статический интерфейс без внешних зависимостей.
- Основной сценарий рассчитан на широкий экран; на узкой ширине навигация
  сворачивается, а недельная сетка прокручивается горизонтально.

## Рассмотренные варианты и обоснования

- **Выбран статический клиент вместо временного крупного фреймворка.** Он
  быстро запускается встроенным HTTP-сервером Python, не хранит логику
  планирования и сохраняет чёткую границу с API. Компонентный фреймворк можно
  внедрить позднее, не меняя контракт сервера.
- **Выбран первый срез страницы «План».** Это ежедневный маршрут с наибольшим
  покрытием функций: он объединяет задачи, свободное время, фиксированные
  события, предложения планировщика и сессию.
- **Визуальная основа — «умная тетрадь» из Stitch.** В код перенесены мягкий
  бумажный фон, моноширинные числовые элементы, синие действия, зелёные окна
  доступности и серая неподвижная сетка.

# Выводы TASK_055 — Разделить изменение повторяющегося события на день и серию

[← К описанию](./055_descr.md) · [Журнал](./055_logs.md)

## Краткий итог

Повторяющееся событие из плана по умолчанию изменяется или убирается только на
выбранной дате; галочка распространяет действие на всю серию.

## Подтверждённые результаты и доказательства

- `FixedEventOccurrence` хранит исключение по паре «правило + локальная дата»;
  отмена не удаляет само правило. Расчёты занятости используют эффективное
  событие на дату, а не только недельный шаблон.
- Интеграционный тест подтвердил изоляцию дат, свободное время, сохранность
  после перезапуска и архивирование серии. `pytest backend/tests`: 36 успешно.
- В открытой форме события текущего дня галочка серии не отмечена.

## Полезные наблюдения

- Существующие правила остаются в `fixed_event_rules`; исключения хранятся
  отдельно. При общем изменении серии локальные правки видимых повторов
  удаляются, а специально отменённые даты остаются отменёнными.
- Связанные знания: [предметная модель](../../knowledge/planirovschik_nedeli.md),
  [база данных](../../knowledge/baza_dannyh_planirovschika.md).

## Проблемы и преграды

- Отдельный экран настроек события продолжает редактировать всё правило;
  выбор «один день / вся серия» относится к действиям непосредственно в плане.

## Как решались проблемы

- Для старой базы добавлена совместимая миграция с резервной копией перед
  созданием таблицы исключений.

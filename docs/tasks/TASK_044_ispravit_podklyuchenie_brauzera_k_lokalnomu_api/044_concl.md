# Выводы TASK_044 — Исправить подключение браузера к локальному API

[← К описанию](./044_descr.md) · [Журнал](./044_logs.md)

## Краткий итог

Клиент больше не остаётся на старом локальном порту из хранилища конкретного
браузера: локальные адреса переводятся на `8100`, а подключение имеет резервную
попытку через штатный адрес.

## Подтверждённые результаты и доказательства

- `node --check frontend/app.js` завершился без ошибок.
- Сервер отдал новую версию `app.js` с функцией нормализации адреса.
- Проверка в интерфейсе с принудительно выбранным `8000` восстановила
  подключение и показала 20 задач и недельное расписание.
- Проверенная ссылка: `http://127.0.0.1:3000/?v=20260914-5`.

## Полезные наблюдения

- Локальное хранилище одного браузера не отражает настройки другого, поэтому
  проверка только во встроенном браузере не исключала старый адрес в браузере
  пользователя.

## Проблемы и преграды

- Старый адрес API и кэш могли сохранять ошибку даже при работающем сервере.

## Как решались проблемы

- Добавлена миграция любого локального адреса на штатный `8100` и обновлена
  версия подключаемого скрипта.

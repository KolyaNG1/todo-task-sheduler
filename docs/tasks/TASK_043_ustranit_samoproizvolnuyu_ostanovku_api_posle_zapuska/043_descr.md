# TASK_043 — Устранить самопроизвольную остановку API после запуска

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./043_logs.md)
- [Выводы](./043_concl.md)

## Цель

Проверить, останавливается ли API самопроизвольно после запуска, когда интерфейс
сообщает `Failed to fetch` на `3000`.

## Границы

### Входит

- Проверка API и интерфейса в момент обращения пользователя.
- Повторная загрузка страницы и отложенная проверка доступности.

### Не входит

- Изменение пользовательских данных и не относящихся к запуску функций.

## Требования пользователя

- 2026-09-14 — пользователь повторно увидел «Не удалось подключиться к серверу.
  Failed to fetch» на `3000`.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] API и интерфейс проверены в момент диагностики и спустя полминуты.
- [x] Страница перезагружена и показала данные.
- [x] Выводы описаны.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Проверить слушающие процессы и ответы обоих адресов.
2. Проверить загрузку API напрямую.
3. Перезагрузить страницу и проверить отображение данных.
4. Повторить проверку с задержкой.

## Допущения и ограничения

- В момент проверки API доступен на `8100`, интерфейс — на `3000`.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- Не считать ошибку вкладки доказательством остановки процесса без проверки
  API и повторной загрузки страницы.

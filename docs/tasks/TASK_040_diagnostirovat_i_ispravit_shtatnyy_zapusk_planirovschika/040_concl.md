# Выводы TASK_040 — Диагностировать и исправить штатный запуск планировщика

[← К описанию](./040_descr.md) · [Журнал](./040_logs.md)

## Краткий итог

Причина плохого запуска устранена: API-порт 8000 оказался запрещён Windows, а
старый bat открывал интерфейс, не проверяя, что API действительно поднялся.

## Подтверждённые результаты и доказательства

- Windows исключает диапазон 7966–8065, в который входит 8000; запуск Uvicorn
  на этом порту дал `WinError 10013`.
- API успешно стартует на 8100 и отвечает `200` на `/api/v1/health`.
- Клиент по умолчанию использует 8100; сохранённый старый адрес 8000 при
  следующей загрузке автоматически заменяется новым.
- `Запустить планировщик.bat` сначала проверяет оба адреса, не плодит процессы
  при повторном запуске, а после запуска ждёт их готовности. При ошибке он
  оставляет понятное окно с причиной вместо открытия пустого интерфейса.
- В ходе проверки интерфейс на 3000 и API на 8100 ответили `200`.

## Полезные наблюдения

- Для пакетных файлов в этой среде обязательны CRLF-строки: файл с одними LF
  запускался `cmd.exe` с обрезанными командами и пустыми переменными.

## Проблемы и преграды

- Окружение `.venv` не содержит Uvicorn, поэтому штатный файл продолжает
  использовать системный Python, где установлены зависимости проекта.

## Как решались проблемы

- Свободный порт 8100 заменил запрещённый 8000 без изменения настроек Windows.
- Ожидание HTTP вынесено из синтаксиса bat в `scripts/wait_for_planner.py`.

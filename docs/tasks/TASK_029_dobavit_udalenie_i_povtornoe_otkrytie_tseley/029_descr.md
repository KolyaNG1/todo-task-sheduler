# TASK_029 — Добавить удаление и повторное открытие целей

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./029_logs.md)
- [Выводы](./029_concl.md)

## Цель

Дать цели полный жизненный цикл: её можно завершить, вернуть из «Готово» в
активную работу и удалить без потери связанных задач, расписания и истории
времени.

## Границы

### Входит

- Серверные действия: повторное открытие завершённой цели и мягкое удаление
  цели.
- При удалении отвязывать задачи от цели, но не удалять их, их дерево, блоки
  расписания и сессии работы.
- Кнопки «Вернуть в активные» и «Удалить» на странице списка и внутри страницы
  цели.
- Подтверждение удаления с ясным сообщением о судьбе задач.
- Автоматические тесты жизненного цикла цели.

### Не входит

- Корзина и восстановление удалённых целей: в текущем интерфейсе цель
  удаляется из видимых сущностей окончательно, хотя запись остаётся в базе для
  целостности журнала.
- Массовое удаление нескольких целей.

## Требования пользователя

- 2026-09-11 — исходный запрос: Добавить удаление и повторное открытие целей.
- 2026-09-11 — пользователь спрашивает, почему цель нельзя удалить и почему
  готовую цель нельзя вернуть в фазу активного достижения.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] Завершённую цель можно вернуть в статус `ACTIVE`; дата завершения
  очищается.
- [x] Удаление цели доступно из списка и страницы цели, требует подтверждения
  и не удаляет её задачи.
- [x] Результат задачи получен и проверен.
- [x] Выводы и проблемы описаны.
- [x] Глобальные знания и решения обновлены.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Проверить текущие маршруты, статусы и привязку задач к цели.
2. Реализовать серверные команды и защищающий их тест.
3. Добавить понятные действия на двух поверхностях интерфейса.
4. Проверить результат и обновить знания.

## Допущения и ограничения

- Удаление цели не должно быть каскадным для задач: пользователь может
  продолжить планировать их отдельно либо прикрепить к новой цели.
- Состояние «готово» — обратимое; повторное открытие не изменяет статусы задач
  и не очищает их фактическое время.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- **Решение:** использовать мягкое удаление `Goal.deleted_at` и отвязку
  `Task.goal_id`, а не физическое удаление или архивирование задач. Так план,
  история работы и дерево задач остаются доступными.
- **Решение:** ввести явный маршрут «повторно открыть», а не разрешать клиенту
  произвольно менять строковый статус через обычное редактирование цели.

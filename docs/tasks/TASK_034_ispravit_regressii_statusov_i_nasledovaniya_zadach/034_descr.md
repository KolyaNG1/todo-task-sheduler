# TASK_034 — Исправить регрессии статусов и наследования задач

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./034_logs.md)
- [Выводы](./034_concl.md)

## Цель

Убрать регрессии предыдущего среза: завершение работы не меняет срок, состояние
видно одинаково в списках и календаре, а создание и изменение потомка не
разрушают дерево задач.

## Границы

### Входит

- Явный признак чекпоинта, независимый от `parent_task_id`.
- Согласование завершения и повторного открытия задачи с блоками расписания и
  уведомлениями о просрочке.
- Исправление обеих форм создания потомка и действий промежуточного чекпоинта.
- Автоматические и ручные проверки сервера и интерфейса.

### Не входит

- Перенос существующего дерева задач между разными целями.
- Новые уровни иерархии или отдельные типы сущностей для проектов и спринтов.

## Требования пользователя

- 2026-09-12 — исходный запрос: Исправить регрессии статусов и наследования задач.

- 2026-09-12 — пользователь уточнил: повторное открытие должно также
  визуально возвращать блок расписания в активное состояние; кнопка «+» обязана
  сразу сохранять выбранного родителя, а снятие признака чекпоинта не должно
  переносить задачу в корень.

## Критерии завершения

- [x] Завершение не меняет срок, закрывает просрочку и синхронизирует блоки.
- [x] Повторное открытие возвращает задачу и завершённые блоки в активное
  состояние.
- [x] Связь с родителем сохраняется независимо от признака чекпоинта.
- [x] Выводы, знания и решение обновлены.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Сверить регрессии с контрактами API и текущими формами.
2. Разделить связь дерева и возможность выполнения на отдельные свойства.
3. Проверить изменения изолированными тестами и в работающем интерфейсе.
4. Обновить знания и решение о дереве задач.

## Допущения и ограничения

- Для обратной совместимости конечная задача остаётся доступной для
  планирования, даже если у неё не указан явный признак чекпоинта.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- Выбран отдельный булев признак `is_checkpoint`, а не вычисление типа только
  по положению в дереве. Иначе промежуточную задачу нельзя выполнить, а снятие
  флажка неотличимо от удаления связи с родителем.

# TASK_046 — Переработать иерархию задач и дневную историю метрик

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./046_logs.md)
- [Выводы](./046_concl.md)

## Цель

Сделать цель корнем произвольного дерева работы, в котором лист является
планируемой задачей, внутренний узел является группой, а группа при явном выборе
может дополнительно выполняться как задача. Добавить рекурсивный прогресс целей,
доступную историю дневных показателей и корректное отображение прошлых
выполненных задач.

## Границы

### Входит

- Исследование проверенных подходов к иерархии и свёртке прогресса.
- Единая серверная классификация листьев, групп и исполняемых групп.
- Создание произвольной глубины через действие `+` у конкретного узла.
- Сворачивание любой ветви дерева и прогресс каждой группы.
- Рекурсивный процент цели и вывод всех целей компактными карточками на плане.
- Сохранение снимков дневных показателей и просмотр итогов за выбранную дату.
- Скрытие прошлых выполненных задач только из списков задач при сохранении их
  блоков и действий в историческом расписании.
- Автоматические, программные и визуальные проверки без поломки прежних
  сценариев.

### Не входит

- Совместная работа нескольких пользователей и права доступа.
- Отдельные сущности «проект» и «спринт» в базе: они моделируются именованными
  группами произвольной глубины.
- Перемещение поддерева между разными целями отдельной массовой операцией.

## Требования пользователя

- 2026-09-16 — цель содержит дерево произвольной глубины: цель → проекты или
  группы → спринты или группы → конкретные задачи.
- 2026-09-16 — задачей является лист дерева; наличие родителя само по себе не
  превращает лист в чекпоинт.
- 2026-09-16 — группа по умолчанию не появляется в ежедневном списке задач, но
  может быть явно отмечена как исполняемая задача и тогда сохраняет оба набора
  возможностей.
- 2026-09-16 — ветви групп раскрываются и сворачиваются, прогресс вычисляется
  снизу вверх для каждой группы и цели.
- 2026-09-16 — на главном экране показываются все цели небольшими карточками с
  процентом.
- 2026-09-16 — итоги и основные показатели относятся к конкретному дню;
  история показателей сохраняется и доступна для прошлых дат.
- 2026-09-16 — выполненная в прошлом задача исчезает только из списков задач,
  но остаётся в расписании с доступными действиями.
- 2026-09-19 — предупреждение о пропущенном сроке относится только к тому дню,
  в который срок был пропущен, не переносится на следующие дни и не дублируется.
- 2026-09-19 — список пропущенных сроков сворачивается в одну заметную плашку
  с числом предупреждений и раскрывается по запросу.
- 2026-09-19 — раздел «Работа по задачам» показывает только фактические сессии
  выбранного дня и обрезает пересекающие полночь сессии границами дня.
- 2026-09-19 — экран итогов сравнивает на единой временной шкале фактические и
  запланированные промежутки выбранного дня в двух соседних колонках.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] Дочерний лист классифицируется как задача, а не как чекпоинт.
- [x] Вложенность создаётся на любой глубине; чистая группа не планируется, а
  исполняемая группа планируется без потери потомков.
- [x] Каждая группа и цель получают проверяемый рекурсивный процент прогресса.
- [x] Все цели видны компактными карточками на плане.
- [x] Итоги можно открыть за выбранный день, а снимки дневных показателей
  сохраняются и выдаются диапазоном.
- [x] Пропущенные сроки не мигрируют между днями, не дублируются и собраны в
  сворачиваемую плашку.
- [x] «Работа по задачам» и сравнение «факт / план» строго ограничены выбранным
  календарным днём, включая сессии и блоки на границе суток.
- [x] Прошлая выполненная задача отсутствует в списках, но её блок остаётся в
  календаре и может быть возвращён в активные.
- [x] Старые проверки и новые регрессионные сценарии проходят.
- [x] Интерфейс проверен в работающем браузере.
- [x] Выводы и проблемы описаны.
- [x] Глобальные знания и решения обновлены.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Сопоставить требование с текущей схемой, интерфейсом и официальными
   подходами других планировщиков.
2. Зафиксировать инварианты узлов, прогресса и дневных снимков.
3. Изменить серверные контракты и совместимую схему хранения.
4. Перестроить списки задач, дерево цели, карточки целей и экран итогов.
5. Добавить регрессионные проверки и прогнать весь набор тестов.
6. Запустить сервис и пройти ключевые сценарии в браузере.
7. Обновить знания, решение и выводы задачи.

## Допущения и ограничения

- Поле `is_checkpoint` сохраняется в программном интерфейсе для совместимости,
  но трактуется как признак «группа также является задачей» только у узла с
  потомками.
- Уровни «проект» и «спринт» являются пользовательскими названиями групп, а не
  жёсткими типами: это сохраняет произвольную глубину.
- Процент группы считается по вложенным рабочим единицам; собственная работа
  исполняемой группы учитывается отдельно от её потомков.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- Не вводить отдельную таблицу для каждого уровня дерева: самоссылка задачи уже
  поддерживает произвольную глубину и проще расширяется.
- Не скрывать прошлые задачи из серверной выдачи старта: календарю нужны их
  названия и состояния. Фильтрация выполняется только в представлениях списков.
- Хранить дневной снимок отдельно от исходных сессий и блоков, чтобы история
  показателей оставалась явно доступной и не зависела от клиентской памяти.

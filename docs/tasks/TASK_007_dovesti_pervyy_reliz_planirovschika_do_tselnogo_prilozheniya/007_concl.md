# Выводы TASK_007 — Довести первый релиз планировщика до цельного приложения

[← К описанию](./007_descr.md) · [Журнал](./007_logs.md)

## Краткий итог

Собран цельный локальный рабочий срез: пользователь может завести направление и
ярлык, создать и разместить задачу, вести сессию, завершить задачу и увидеть
итог дня. Задача остаётся активной для редких административных и жестовых
сценариев, которые ещё не доведены до уровня полного ТЗ.

## Подтверждённые результаты и доказательства

- Сервер получил HTTP-методы изменения и жизненного цикла задач, изменения и
  отмены блока, выдачи истории сессий и дневного вычисляемого итога.
- Автоматическая проверка охватывает новый путь: изменение задачи, перенос
  блока, ручная сессия, итог дня, архивирование и возврат задачи.
- Браузерный клиент получил пять основных разделов. Он остаётся статическим и
  вызывает только API, а не базу данных.
- Локальный API и клиент отвечают по адресам `127.0.0.1:8000` и
  `127.0.0.1:5173`; в браузере подтверждены загрузка плана и раздел «Задачи».
- Базовый ежедневный поток стал самодостаточным: до трёх рабочих интервалов на
  дату, редактирование задачи и ввод фактических минут при завершении доступны
  через обычные формы приложения.
- Рабочие панели можно временно скрыть без потери состояния: вариант плана
  возвращается из панели инструментов, а активная сессия — отдельной компактной
  кнопкой. Кнопка «Зафиксировать работу» сохраняет работу вручную даже без
  таймера.
- Нижняя панель плана переработана после ошибки раскладки: кнопка скрытия всегда
  доступна. Все краткие уведомления получили крестик, а рабочие интервалы стали
  динамическим списком. Ручное размещение поддерживает перетаскивание карточки
  задачи на 15-минутную сетку.

## Полезные наблюдения

- Вычисляемый дневной итог не требует отдельного хранилища для первого
  законченного сценария: источником являются сессии и подтверждённые блоки.
  Снимки с ревизиями остаются следующим улучшением для отчётности.
- Ярлыки уже поддерживаются сервером; клиент загружает их отдельным запросом и
  передаёт список идентификаторов при создании задачи.
- Системный запрос браузера для ввода времени заменён модальным окном
  приложения: он не выглядит как ошибка и не прерывает рабочий сценарий.

## Проблемы и преграды

- Запущенный ранее сервер необходимо перезапускать после изменения Python-кода;
  иначе браузер продолжает обращаться к старому набору маршрутов.
- В проверке переноса блока обнаружено, что прежний блок попадал в собственную
  проверку пересечений до сброса в базу.
- Крестики панелей меняли свойство `hidden`, но панели оставались видимыми:
  явные правила `display: grid/flex` в стилях перекрывали стандартное поведение
  браузера для скрытых элементов.

## Как решались проблемы

- Перед поиском нового пересечения старый блок временно получает статус
  `CANCELLED` и изменения сбрасываются в текущую транзакцию; затем применяются
  новые время и состояние.
- Сервер перезапущен, клиент перезагружен; стартовые запросы к API подтверждены
  отдельно от браузерной отрисовки.
- Добавлено общее CSS-правило для `[hidden]`, поэтому закрытие рабочей сессии и
  предварительного плана теперь физически убирает их с экрана; предусмотренные
  кнопки восстановления сохраняют доступ к состоянию.

## Открытые вопросы

- Редактор существующих задач и неподвижных событий, несколько интервалов
  доступности в одном окне, перетаскивание и изменение размера блоков должны
  получить отдельный интерфейсный срез.
- Административное окончательное удаление с показом последствий и сохранённые
  снимки отчётов пока не реализованы. Цели, Telegram и программный агент
  остаются намеренно отложенными в ТЗ.

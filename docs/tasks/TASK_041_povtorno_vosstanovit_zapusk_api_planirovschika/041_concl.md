# Выводы TASK_041 — Повторно восстановить запуск API планировщика

[← К описанию](./041_descr.md) · [Журнал](./041_logs.md)

## Краткий итог

Повторный сбой не был проблемой порта или данных: у `Запустить
планировщик.bat` смешались переводы строк CRLF и LF. После приведения файла к
CRLF штатный запуск снова поднял обе части приложения.

## Подтверждённые результаты и доказательства

- До исправления интерфейс на `3000` открывался без API и показывал `Failed to
  fetch`.
- Проверка байтов файла обнаружила LF после строк с настройками портов, хотя
  начало файла было в CRLF.
- После исправления `scripts/wait_for_planner.py` успешно подтвердил оба
  адреса: API `http://127.0.0.1:8100/api/v1/health` и интерфейс
  `http://127.0.0.1:3000/`.
- Обновлённая вкладка загрузила список задач и недельное расписание.

## Полезные наблюдения

- Для пакетных файлов этого проекта любое изменение должно сохранять CRLF;
  иначе `cmd.exe` может неверно разобрать последующие команды.

## Проблемы и преграды

- Смешанный формат строк в пакетном файле не виден обычным просмотром текста,
  но ломает его выполнение в Windows.

## Как решались проблемы

- Механически нормализован весь файл, а не отдельные строки, чтобы исключить
  повторное появление смешанного формата.

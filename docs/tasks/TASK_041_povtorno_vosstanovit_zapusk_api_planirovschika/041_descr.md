# TASK_041 — Повторно восстановить запуск API планировщика

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./041_logs.md)
- [Выводы](./041_concl.md)

## Цель

Вернуть надёжный запуск API через `Запустить планировщик.bat`, когда интерфейс
на `3000` открывается, но сообщает, что сервер не запущен.

## Границы

### Входит

- Проверка состояния интерфейса и API после штатного запуска.
- Диагностика пакетного файла и исправление его формата.
- Проверка доступности API на `8100` и интерфейса на `3000`.

### Не входит

- Изменение данных планировщика и завершение уже работающих процессов.

## Требования пользователя

- 2026-09-14 — на `http://127.0.0.1:3000/` интерфейс показал «Сервер не
  запущен» и `Failed to fetch`.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] API и интерфейс снова отвечают на штатных адресах.
- [x] Формат пакетного файла исправлен.
- [x] Выводы и проблема описаны.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Проверить ошибку интерфейса и состояние обоих адресов.
2. Проверить байтовый формат пакетного файла.
3. Привести переводы строк к формату Windows и повторно запустить.
4. Проверить API, интерфейс и документацию.

## Допущения и ограничения

- Приложение продолжает использовать порты, выбранные в TASK_040: API `8100`
  и интерфейс `3000`.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- Не менять порты и прикладной код: ошибка воспроизводилась ещё до обращения
  клиента, на уровне выполнения `.bat`.
- Привести весь файл к CRLF — штатному формату перевода строк Windows, а не
  исправлять отдельные команды.

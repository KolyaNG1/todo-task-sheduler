# Выводы TASK_050 — Расширить недельные дедлайны и ограничить автоплан сегодняшним днём

[← К описанию](./050_descr.md) · [Журнал](./050_logs.md)

## Краткий итог

Недельные дедлайны стали проверяемой частью недельного снимка: интерфейс
показывает состав дедлайнов дня, оставшуюся работу недели и запас либо дефицит
свободного времени. Автоплан не может размещать новые блоки раньше текущего
момента. Редактор блока из календаря теперь одновременно редактирует задачу и
её размещение и принимает время с точностью до минуты.

## Подтверждённые результаты и доказательства

- `week_view` возвращает для каждого дня `deadline_tasks`, а для первых семи
  дней — `deadline_workload` с количеством задач, оставшимися минутами,
  доступными минутами и балансом.
- Уже подтверждённые минуты блоков вычитаются из оценки задачи; доступность
  считается только от текущего момента и до последнего срока недели.
- Сервер применяет `max(запрошенное начало, текущее время)` и отклоняет полностью
  прошлый диапазон. Клиент также останавливает такой запуск до запроса.
- Карандаш блока открывает обычные параметры задачи и отдельный раздел
  размещения. Изменение времени блока не переносит срок задачи автоматически.
- Поля начала и конца используют минутный шаг; браузер принял `12:50`.
- Сервер принимает произвольную минуту начала и конца как при создании, так и
  при изменении ручного блока; 15-минутная сетка остаётся правилом размещения
  автоматического планировщика, а не ограничением ручного ввода.
- `python -m pytest backend/tests -q` — 34 успешных теста; `node --check
  frontend/app.js` и `git diff --check` не нашли ошибок.
- Живая проверка на `http://127.0.0.1:3000/` подтвердила подсказку со списком
  задач, недельный дефицит, объединённый редактор и отсутствие ошибок консоли.

## Полезные наблюдения

- Для дедлайнов и недельной нагрузки нужен один серверный снимок: отдельный
  запрос по наведению создавал бы гонку с уже показанной неделей.
- Ограничение автоплана только на клиенте недостаточно: сервер должен защищать
  тот же инвариант для любого будущего клиента.

## Проблемы и преграды

- После первой проверки порт 8100 обслуживал прежний процесс и старую схему,
  поэтому новые поля не отображались в браузере.

## Как решались проблемы

- Прежний процесс был остановлен, сервис запущен штатным bat-файлом, а версия
  ответа повторно проверена непосредственно через API до браузерной проверки.

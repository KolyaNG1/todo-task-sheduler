# TASK_050 — Расширить недельные дедлайны и ограничить автоплан сегодняшним днём

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./050_logs.md)
- [Выводы](./050_concl.md)

## Цель

Сделать недельную нагрузку по дедлайнам прозрачной и не допускать размещения
новой автоматической планировки в прошлом независимо от открытой недели.

## Границы

### Входит

- Список задач во всплывающей подсказке дневного счётчика дедлайнов.
- Недельная оценка оставшегося времени задач со сроками.
- Сопоставление этой оценки с доступным для планирования временем до сроков.
- Нижняя граница автоматического планирования: текущий момент/сегодня, а не
  начало открытой недели.
- Объединённое редактирование задачи и её конкретного блока из расписания.
- Серверные проверки расчётов и ручная проверка поведения интерфейса.

### Не входит

- Изменение самих сроков задач или автоматический перенос просроченных задач.
- Перепроектирование алгоритма приоритетов сверх ограничения нижней даты.

## Требования пользователя

- 2026-09-21 — при наведении на кружок количества дедлайнов показывать названия
  задач, срок которых приходится на этот день.
- 2026-09-21 — показывать, сколько часов задач со сроками нужно выполнить за
  неделю и сколько доступного времени ещё остаётся либо не хватает.
- 2026-09-21 — автоматическая планировка никогда не должна начинаться раньше
  сегодняшнего дня, даже если пользователь открыл прошлую неделю.
- 2026-09-21 — карандаш на задаче непосредственно в плане должен позволять
  редактировать не только время блока, но и стандартные параметры самой задачи.
- 2026-09-21 — в ручном редакторе блока начало и конец должны принимать любое
  время с точностью до минуты, а не только значения с шагом 15 минут.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] Дневной счётчик раскрывает список соответствующих активных задач.
- [x] Недельная сводка показывает оставшуюся оценку задач со сроками и доступное
  время до сроков без двойного учёта уже размещённых минут.
- [x] Автоплан при открытой прошлой неделе не создаёт блоки в прошлом.
- [x] Карандаш блока открывает стандартные параметры задачи и параметры
  размещения; сохранение корректно обновляет обе сущности.
- [x] Ручное время блока принимает минутные значения, например 12:50.
- [x] Пограничные расчёты покрыты автоматическими тестами.
- [x] Результат задачи получен и проверен.
- [x] Выводы и проблемы описаны.
- [x] Глобальные знания и решения обновлены.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Проследить поток данных дедлайнов и автоплана от сервера до календаря.
2. Определить однозначные формулы недельной нагрузки и доступного времени.
3. Реализовать серверные данные, интерфейс подсказки и сводки.
4. Закрепить нижнюю границу автоплана на сервере и проверить прошлую неделю.
5. Выполнить автоматические и браузерные проверки, обновить документацию.

## Допущения и ограничения

- В нагрузку входят активные выполняемые задачи с дедлайном в отображаемой
  неделе. Оставшаяся работа равна оценке минус уже подтверждённые минуты.
- Доступным считается свободное рабочее время от сегодняшнего момента до
  соответствующих сроков внутри отображаемой недели.
- Для открытой прошлой недели ожидаемый результат автоплана — отсутствие новых
  блоков, а не перенос их в прошлое.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- Источник истины для ограничения дат должен быть на сервере: одной клиентской
  блокировки недостаточно для других клиентов программного интерфейса.
- Подсказка дедлайнов строится из уже загруженного недельного снимка, если сервер
  отдаёт сами задачи вместе с числом, чтобы не создавать запрос при наведении.

# TASK_028 — Переработать интерфейс целей и иерархии задач

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./028_logs.md)
- [Выводы](./028_concl.md)

## Цель

Сделать иерархию задач понятной в ежедневной работе: общий банк остаётся
плоским и компактным, а структура видна в отдельной странице цели. Переработать
панель добавления задачи в цели и отображение активных целей на плане.

## Границы

### Входит

- Сворачиваемая панель прямого добавления задачи на странице цели: закрыта по
  умолчанию, открывается явной кнопкой и закрывается крестиком.
- Компактная сетка карточек активных целей на странице плана: только название
  и процент, без растягивания строки на всю ширину.
- Плоское выравнивание карточек дочерних задач в общем банке и на общем экране
  задач; связь с родителем остаётся короткой подписью.
- Исправление порядка корневых задач цели после сохранения, чтобы дочерние
  задачи не попадали в последовательность верхнего уровня.
- Уточнение серверного правила: нельзя превратить уже запланированную задачу в
  родительскую незаметно, иначе её работа была бы одновременно у родителя и
  чекпоинтов.

### Не входит

- Изменение модели SQLite и перенос существующих данных.
- Полноценное перемещение или копирование целого поддерева между целями.

## Требования пользователя

- 2026-09-11 — исходный запрос: Переработать интерфейс целей и иерархии задач.
- 2026-09-11 — панель прямого добавления задачи в цели должна скрываться.
- 2026-09-11 — карточки целей на плане должны быть примерно квадратными и
  содержать только название и процент прогресса.
- 2026-09-11 — дочерние задачи не должны получать визуальный сдвиг в общем
  списке задач.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [x] Форма новой задачи цели закрыта по умолчанию, открывается и закрывается
  без потери данных формы.
- [x] Карточки активных целей не растягиваются по ширине страницы и показывают
  только название и процент.
- [x] В банке и общем списке карточки задач выровнены независимо от глубины.
- [x] Сохранение последовательности цели хранит только корневые пункты.
- [x] Задача с действующим блоком не становится родителем без явного снятия из
  плана.
- [x] Результат задачи проверен в браузере и автоматическими тестами.
- [x] Выводы и знания обновлены.
- [x] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Зафиксировать границы представления дерева и инвариант перехода в родителя.
2. Переработать компактное представление целей и форму создания в цели.
3. Убрать отступы из общих списков и исправить последовательность корней.
4. Проверить серверное ограничение, фронтенд и браузерный результат.
5. Обновить документацию и выполнить её проверку.

## Допущения и ограничения

- Иерархия остаётся видна на странице цели, где отступ нужен для понимания
  структуры; общий банк служит для выбора и планирования, поэтому он плоский.
- Превращение атомарной задачи в группу допускается до её размещения. Если у
  неё есть подтверждённые блоки, пользователь сначала снимает их из плана.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- **Решение:** не скрывать дочерние задачи из общего банка. Они остаются
  доступными для поиска, запуска и планирования, но получают краткую подпись о
  родителе вместо сдвига в сторону.
- **Решение:** не добавлять второй тип «проект». Обычная задача становится
  группой, когда у неё появляется первый чекпоинт; сервер защищает от
  дублирования уже размещённой работы.

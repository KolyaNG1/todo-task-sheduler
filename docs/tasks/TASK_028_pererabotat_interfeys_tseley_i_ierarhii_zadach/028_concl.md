# Выводы TASK_028 — Переработать интерфейс целей и иерархии задач

[← К описанию](./028_descr.md) · [Журнал](./028_logs.md)

## Краткий итог

Интерфейс целей и иерархии задач приведён к двум разным сценариям: в общем
банке задача остаётся компактной плоской карточкой, а дерево редактируется на
странице конкретной цели. Сервер не допускает двойного смысла у уже
запланированной работы.

## Подтверждённые результаты и доказательства

- На странице цели форма добавления пункта скрыта по умолчанию. Кнопка
  «Добавить» открывает её рядом с деревом, крестик закрывает; введённые поля
  сохраняются до повторного открытия.
- На странице плана активные цели показаны карточками 116×92 пикселя с одним
  названием и процентом. Блок можно скрыть крестиком и вернуть кнопкой
  «Цели».
- В банке и общем списке дочерняя задача больше не получает отступ: связь
  отображается текстом `чекпоинт · родитель`. Отступы сохранены только в
  дереве страницы цели.
- При сохранении порядка цели в API уходят только корневые задачи, поэтому
  дочерние не становятся ошибочными элементами верхней последовательности.
- `PlannerService` отклоняет создание или перенос чекпоинта под задачу с
  подтверждённым блоком; запуск и ручная запись времени для задачи-группы
  также отклоняются.
- Автоматические проверки: 19 тестов успешно, синтаксис клиента и компиляция
  сервера успешны, проверка различий не выявила пробельных ошибок. Локальная
  браузерная проверка подтвердила размер и содержание карточки цели, а также
  плоское отображение чекпоинта.

## Полезные наблюдения

- Витрина целей и рабочее дерево — разные поверхности: попытка показать всё
  дерево в банке делает ежедневное планирование визуально тяжелее.
- Для любых будущих уровней («проект», «спринт») достаточно обычной задачи с
  потомками; отдельная таблица типа уровня не требуется.

## Проблемы и преграды

- Существенных препятствий не осталось.

## Как решались проблемы

- Правило дерева уточнено в
  [DEC_005](../../decisions/DECISION_005_derevo_zadach_i_istochnik_vremeni.md):
  контейнеры не участвуют в плане и учёте времени.

## Открытые вопросы

- Будущее безопасное перемещение поддерева между целями требует отдельного
  сценария с подтверждением; в эту задачу не входило.

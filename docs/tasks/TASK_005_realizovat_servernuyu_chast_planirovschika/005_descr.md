# TASK_005 — Реализовать серверную часть планировщика

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./005_logs.md)
- [Выводы](./005_concl.md)

## Цель

Реализовать запускаемую серверную часть планировщика по
[BACKEND_DESIGN.md](../../../BACKEND_DESIGN.md): независимый от клиента
прикладной слой, SQLite внутри `artifacts/`, HTTP-адаптер FastAPI, миграции,
календарь, задачи, планирование и учёт времени.

## Границы

### Входит

- Реализация первых рабочих серверных модулей и их тестов.
- Начальная миграция SQLite, переносимый каталог, манифест и запуск приложения.
- Направления, ярлыки, задачи, рабочее время, неподвижные события, блоки,
  недельный снимок, предварительный план и таймер.
- Версионированный HTTP API, пригодный для браузера и будущих адаптеров.

### Не входит

- Реализация браузерного интерфейса, Telegram-бота и запуска агента.
- Внешняя авторизация, синхронизация с календарями и многопользовательское
  интернет-развёртывание.

## Требования пользователя

- 2026-09-09 — исходный запрос: реализовать серверную часть планировщика.
- 2026-09-09 — учитывать доступные макеты Google Stitch при формировании
  серверных моделей чтения; обращения к базе остаются скрыты от интерфейса.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## Критерии завершения

- [ ] Созданы пакет сервера, миграции, настройки и переносимое хранилище.
- [ ] Реализованы и проверены базовые сценарии задач, календаря и таймера.
- [ ] HTTP API не содержит бизнес-правил и не открывает SQLite напрямую.
- [ ] Реализован и проверен предварительный автоматический план.
- [ ] Результат задачи получен и проверен.
- [ ] Выводы и проблемы описаны.
- [ ] Глобальные знания и решения обновлены.
- [ ] `python scripts/docs_ctl.py check` завершился без ошибок.

## План

1. Зафиксировать [план реализации](../../../IMPLEMENTATION_PLAN.md) и сверить
   модели чтения с макетами Stitch.
2. Создать основу пакета, SQLite, миграции и переносимые артефакты.
3. Реализовать справочники, задачи и календарь через общий прикладной слой.
4. Добавить чистый планировщик, таймер и HTTP-адаптер.
5. Написать тесты, запустить проверки и обновить документацию.

## Допущения и ограничения

- Первая версия работает одним локальным процессом и создаёт одну начальную
  рабочую область автоматически.
- Для первой итерации HTTP не требует входа: локальный владелец выбирается из
  созданной рабочей области. Будущая авторизация заменит этот адаптер.
- Макеты Stitch используются как источник состава экранных моделей, а не как
  источник предметных правил.

## Уточнения наследуемого контекста

- Если задача дочерняя, перечислите только уточнения и допустимые
  переопределения. Остальной контекст читается из задач-предков.

## Рассмотренные варианты и обоснования

- Начинаем с вертикального среза, который уже поддерживает главный экран недели,
  список задач, направления и глобальный таймер. Это даёт фронтенду стабильную
  основу раньше, чем реализация редко используемого администрирования.
- Шаблоны и исключения календаря хранятся раздельно: это соответствует макету
  сетки и не создаёт тысячи повторяющихся строк на будущее.
- Планировщик сначала реализуется простым детерминированным алгоритмом с
  предварительным вариантом. Улучшение оценки остаётся отдельной заменяемой
  функцией предметного слоя.

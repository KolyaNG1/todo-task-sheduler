# DEC_005 — Дерево задач и единый источник фактического времени

[← К журналу решений](index.md)

## Контекст

Планировщику нужны большие задачи с декомпозицией на проекты, спринты и
конкретные действия. Одновременно пользователь должен видеть не только итог
дня, но и интервалы работы над конкретной задачей. Отдельные сущности для
каждого уровня или дублирование времени в задаче создадут лишние источники
истины и риск двойного подсчёта.

## Решение

1. Каждая задача может ссылаться на родителя через `parent_task_id`; порядок
   соседей хранится в `child_position`.
2. Свойство `is_checkpoint` отдельно хранит намерение выполнять задачу как
   самостоятельную работу. Оно не меняет `parent_task_id` и может быть включено
   у промежуточного узла с потомками.
3. Календарь, автоплан, запуск и завершение используют конечные задачи и
   промежуточные узлы с `is_checkpoint = true`. Обычный узел с потомками
   остаётся организационной группой.
4. `WorkSession` и `WorkSessionSegment` остаются единственным источником
   фактического времени. API строит из них два представления: хронологию дня и
   группировку «задача → сессия → интервал».
5. В общем списке задача остаётся плоской карточкой с подписью о родителе;
   дерево с отступами — это представление только страницы конкретной цели.
6. Архивирование цели не удаляет и не отвязывает дерево задач: связь и порядок
   сохраняются для восстановления. Окончательное удаление доступно только из
   архива; связанные блоки и история времени сохраняются как история.
7. Статус «чекпоинт» — задача с `is_checkpoint = true`, «группа» — узел с
   потомками без этого признака, «задача» — конечный пункт без признака. Это
   единая модель `Task`: вид в списке не изменяет ни положение в дереве, ни
   данные о сроке, сессиях и блоках.

## Последствия

- Одна модель покрывает любое число уровней без новой таблицы «проектов» или
  «спринтов».
- Готовый узел не может случайно скрыть незавершённые пункты: обычная группа
  недоступна для завершения, а выполненный чекпоинт сохраняет дерево и может
  быть возвращён в активные.
- Новые клиенты, включая будущие Telegram-бот и агент, используют тот же API и
  не поддерживают собственный журнал времени.
- Для перемещения целого поддерева нужен будущий отдельный сценарий с явным
  подтверждением, а не массовое редактирование без проверки.

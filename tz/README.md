# Техническое задание: планировщик недели

Статус: проект требований для согласования. Версия: 0.1 от 2026-09-08.

[Связанная задача Wiki‑LLM](../docs/tasks/TASK_001_podgotovit_tz_prilozheniya_planirovschika_nedeli/001_descr.md)

## 1. Назначение продукта

Приложение помогает одному человеку совмещать учёбу в вузе, работу, спорт и
личные дела. Пользователь задаёт время, в которое он готов работать, заносит
неподвижное расписание и список задач, а система показывает вместимость недели и
предлагает размещение задач с учётом сроков и важности.

Основной экран похож на умную табличную сетку: дни являются столбцами, время —
строками с шагом 15 минут, а задачи и события — цветными блоками. При этом
таблица является представлением данных, а не местом хранения бизнес-логики.

## 2. Цели первой версии

1. Дать понятный обзор выбранной недели и остатка рабочего времени.
2. Позволить вручную задать доступные рабочие интервалы и неподвижные события.
3. Вести единый незавершённый список задач с группами, ярлыками, сроками,
   важностью и оценкой длительности.
4. Размещать задачи вручную и автоматически, в том числе выбранной пачкой.
5. Явно показывать недостаток вместимости, пересечения и просроченные задачи.
6. Сохранять фактическое рабочее время через таймер и ручной ввод.
7. Собирать дневной отчёт о плане, факте и незавершённых обязательствах.
8. Хранить историю без автоматического удаления выполненных задач.

## 3. Не входит в первую версию

- Telegram-бот и любые другие внешние каналы управления.
- Запуск Codex CLI или другого программного агента.
- Совместная работа нескольких пользователей.
- Синхронизация с внешними календарями.
- Полноценное мобильное приложение; интерфейс браузера должен лишь оставаться
  пригодным для просмотра на узком экране.
- Сложное машинное обучение. Планировщик первой версии должен быть
  детерминированным: одинаковые входные данные дают одинаковый результат.

Архитектура обязана оставить точки расширения для перечисленных возможностей.

## 5. Общие определения

**Группа** — расширяемая родительская сущность для задач: учебный предмет,
рабочий проект, спорт, личное направление и иной тип. Группа задаёт цвет,
допустимые ярлыки и значения по умолчанию.

**Задача** — единица результата, которую можно оценить, запланировать, выполнить
и связать с группой. Одна задача может быть разбита на несколько блоков.

**Ярлык** — пользовательская метка вроде «ДЗ», «лекция», «работа» или «спорт».
Ярлыки не заменяют системные состояния.

**Рабочий интервал** — время, которое пользователь разрешил планировщику
использовать для задач.

**Неподвижное событие** — занятое время из обязательного расписания. Оно
блокирует автоматическое планирование и не перетаскивается на недельной сетке.

**Блок задачи** — конкретное размещение части задачи в календаре с началом,
окончанием, источником размещения и признаком ручной фиксации.

**Свободная вместимость** — рабочие интервалы за вычетом неподвижных событий,
размещённых незавершённых блоков и подтверждённых пересечений.

**Пересечение** — ситуация, когда два занятых блока используют одно время либо
блок задачи выходит за доступный рабочий интервал. Пересечение всегда заметно и
не считается обычным свободным временем.

**Рабочая сессия** — фактически затраченное время, записанное таймером или
вручную; она может относиться к задаче, группе либо общему рабочему времени.

## 6. Основные проектные положения

- Шаг времени равен 15 минутам. Оценки и границы, введённые не по сетке,
  округляются вверх при планировании, но исходное фактическое время хранится без
  потери точности.
- Неделя начинается в понедельник. Часовой пояс первой рабочей области по
  умолчанию — `Europe/Moscow`, но он является настройкой.
- Жизненный цикл задачи и состояние планирования независимы. Например, активная
  задача может быть не запланирована, запланирована частично или иметь конфликт.
- Важность задаётся весом из ряда 1, 2, 3, 5, 8, 13, 21. Чем больше число, тем
  выше важность. Срочность вычисляется отдельно из срока.
- Автоматический план сначала показывается как предварительный вариант. Запись
  в постоянное расписание происходит только после подтверждения пользователя.
- Ручные блоки и явно закреплённые автоматические блоки не двигаются при
  последующих автоматических запусках.
- Выполненная задача исчезает из активного списка, но остаётся в истории вместе
  с плановыми блоками и фактическими сессиями до удаления из административного
  раздела.

## 7. Приоритет требований

Формулировки «обязательно» и «должно» являются условиями первой версии.
Формулировка «желательно» означает возможность после основной приёмки.
Предложения, требующие проверки с пользователем, перечислены отдельно в файле
[открытых вопросов](06_otkrytye_voprosy.md).
